Please review the current git diff. Read surrounding code as needed to understand the changes and their intended behavior.

Focus on actionable issues introduced by these changes: bugs, regressions, or design problems with a concrete impact on correctness, security, performance, or maintainability.

Use judgment about what deserves attention:
- For each finding, explain the specific scenario in which it matters and its practical consequence. Ground it in the code or project context rather than speculative assumptions.
- Match the severity and wording to the likely impact. Distinguish confirmed problems from uncertainty.
- Avoid style preferences, minor cleanup, and generic best-practice advice unless they address a concrete problem here.
- Consider existing conventions and reasonable tradeoffs before calling something an issue.

There is no target number of findings. If nothing meaningful needs fixing, say so. Prefer a few well-supported findings over a long list of weak ones.
